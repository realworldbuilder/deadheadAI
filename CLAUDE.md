# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Nethead (formerly TapeTree and Deadhead AI; repo name ShakedownAI) — a native SwiftUI iOS app (iOS 18+, Swift 6) that layers AI discovery over the Internet Archive's Grateful Dead collection. Audio streams from archive.org via AVPlayer; the app re-hosts no recordings, though users can save shows to the device for offline listening.

## Commands

The `.xcodeproj` is **generated** — all project config lives in [project.yml](project.yml). Never edit the `.xcodeproj` by hand; after adding/removing files or changing settings, run:

```bash
xcodegen generate
```

Build and test (simulator builds skip signing). The `OS=` pin matters: without it xcodebuild resolves `OS:latest`, and on hosts whose newest runtime has no iPhone 16 Pro device the build fails with "Unable to find a device". If 18.6 isn't installed, pick any installed pairing from `xcrun simctl list devices available`:

```bash
xcodebuild -project ShakedownAI.xcodeproj -scheme ShakedownAI \
  -destination 'platform=iOS Simulator,name=iPhone 16 Pro,OS=18.6' \
  CODE_SIGNING_ALLOWED=NO build

xcodebuild -project ShakedownAI.xcodeproj -scheme ShakedownAI \
  -destination 'platform=iOS Simulator,name=iPhone 16 Pro,OS=18.6' \
  CODE_SIGNING_ALLOWED=NO test
```

Run a single test (Swift Testing framework, not XCTest):

```bash
xcodebuild -project ShakedownAI.xcodeproj -scheme ShakedownAI \
  -destination 'platform=iOS Simulator,name=iPhone 16 Pro,OS=18.6' \
  CODE_SIGNING_ALLOWED=NO \
  -only-testing:ShakedownAITests/SmartCollectionTests test
```

Install on a physical iPhone: `./run-on-phone.sh` (plugged in, unlocked, trusted).

Debug launch arguments: `--demo-autoplay` (streams Cornell '77, logs to subsystem `ai.deadheads`), `--demo-download` (downloads Cornell '77 and logs progress, for verifying the offline pipeline from the CLI), `--tab explore|chat|library|settings`, `--stage-show` / `--stage-player` (open Cornell '77's show page / full-screen player for CLI screenshot capture), `--stage-year 1977` (open that year's month-by-month browse the same way), `--stage-show 1972-05-04` (stage another night, e.g. one with no memorabilia scans), `--stage-scans` (with `--stage-show`, open the full-screen scan viewer on the night's first scan). `--stage-explore eras|songs|journeys|search|years|topShelf|onThisDay|journal|taste|darkStar` (with `--tab explore`, open that destination straight from the sky) and `--stage-era europe-wall` (that era's page).

## Releasing

Push to `main` → CI tests, then archives and uploads to TestFlight ([.github/workflows/ci.yml](.github/workflows/ci.yml)). PRs run tests only. `CFBundleVersion` is stamped from the CI run number — never bump it by hand; bump `MARKETING_VERSION` in project.yml for new App Store versions. The bundle ID must stay `com.deadhead.ai` (matches the App Store Connect record).

## Architecture

- **Swift 6 approachable concurrency**: `SWIFT_DEFAULT_ACTOR_ISOLATION: MainActor` project-wide. Everything is MainActor by default; networking/parsing code opts out with `nonisolated`. Provider protocols are MainActor-isolated and `await` into the nonisolated networking layer.
- **Dependency injection**: `AppEnvironment` ([ShakedownAI/App/AppEnvironment.swift](ShakedownAI/App/AppEnvironment.swift)) is the single container, injected via `.environment(...)`. `AppEnvironment.live()` wires archive.org providers; `.mock()` wires in-memory mocks for previews/tests.
- **Provider seams** ([ShakedownAI/Core/Providers/Providers.swift](ShakedownAI/Core/Providers/Providers.swift)): `LiveRecordingProvider`, `MetadataProvider`, `StreamingProvider`, `AIProvider`, `AuthProvider`, `SocialProvider`. UI only talks to protocols. `ArchiveShowProvider` backs recording/metadata against archive.org with TTL caching; `CatalogFirstShowProvider` decorates it, answering from the bundled catalog first (see below) and falling through to the network. `MockSocialProvider` and `MockAuthProvider` back the demo social layer and local accounts — a real backend would plug in at those seams.
- **Bundled show catalog** (`Core/Catalog/`, resource `Resources/catalog/catalog.sqlite`, built by [tools/catalog-pipeline](tools/catalog-pipeline/README.md)): every show 1965–95 with real setlists (sets/encores/segues from the cs.cmu.edu archive), every archive.org tape with pipeline-detected source type (SBD/MTX/FM/AUD from identifier + lineage — not the old substring sniff) and a precomputed `quality_score`, an FTS5 index whose blob pre-expands date variants (`5-8-77`, `5/8/77`, `may 8 1977`) plus songs/venues/synthetic tags, and optional per-show AI review digests. Read via raw `SQLite3` (no SPM deps): `CatalogDB` is a `nonisolated actor` owning the handle; `CatalogStore` is the MainActor facade behind the `ShowCatalog` protocol on `AppEnvironment.catalog`. Missing/corrupt/schema-mismatched catalog ⇒ `isAvailable == false` and the app behaves exactly as before (network-only) — keep that invariant. `SetlistMatcher` aligns setlist entries to a tape's tracks with `RunResolver`-style whole-word matching, and `TapeSetlist` lays the tape's tracks out as one "Setlist" list shaped by it (set headings, segue marks, dimmed rows for songs the tape lacks) — tracks are the rows, so tuning/crowd files stay reachable; `Track.displayTitle` strips archive.org's leading track numbers for display. Schema 3 adds `recording_tracks`: for the top four tapes per show (stage 2b, `make tracks`, ~7k `/metadata/{id}/files` fetches, ~30 min cold, resume-safe), the tape's tracks as compact `[title, seconds, file name]` triples in play order — selected and titled by `tools/catalog-pipeline/pipeline/tracks.py`, a mirror of `ArchiveAPIClient.playableFiles`/`titleFromFileName`, so `RunResolver` sees the same titles offline as the live detail call would. `catalog.tracks(forRecording:)` returns nil for tapes stage 2b never fetched. The bundled catalog is ~22 MB (gate: 24 MB), ~7 MB of it tracks. Tests run against `ShakedownAITests/Fixtures/catalog-fixture.sqlite` (`make fixture`). Schema changes must bump `SCHEMA_VERSION` (pipeline) and `expectedSchemaVersion` (`CatalogDB`) together.
- **AI fallback chain**: `CompositeAIProvider` ([ShakedownAI/Core/AI/OpenAIResponsesAI.swift](ShakedownAI/Core/AI/OpenAIResponsesAI.swift)) tries three tiers per call, best first: the OpenAI Responses API when `KeychainStore.resolveAPIKey()` returns a key; then `AppleOnDeviceAI` ([ShakedownAI/Core/AI/AppleOnDeviceAI.swift](ShakedownAI/Core/AI/AppleOnDeviceAI.swift)), Apple's free on-device Foundation Models brain, when the device reports the model ready; then `LocalKnowledgeAI` — a deterministic offline brain over the bundled knowledge base (`ShakedownAI/Resources/knowledge_base/*.json`: curated shows, song histories, eras, journeys, quotes). The build-time bundled key (Info.plist `OpenAIAPIKey`) is used by every user with no sign-in — there is no client-side gate (a UserDefaults flag can't protect a key that ships in the IPA); the spend ceiling is the hard budget limit on the OpenAI project. Sign in with Apple only turns on iCloud sync. Prompts are grounded: the model only chooses among real archive candidates and real setlists. The app must remain fully functional with no key and no sign-in.
- **On-device AI**: `AppleOnDeviceAI` is gated behind `#if canImport(FoundationModels)` (so older Xcode still builds) and `@available(iOS 26.0, *)`, and needs Apple Intelligence hardware. It is a ~3B model with a ~4k context window, so its prompts are far tighter than the OpenAI ones and it selects candidates *by number* rather than reproducing archive identifiers. `OnDeviceAnswer` holds the small-model guard rails (index clamping, blank-optional handling, dropping invented song titles, filtering the stream's `"null"` placeholder); it lives outside the availability gate so it stays unit-testable on any simulator. Verify changes to it against a real iOS 26 simulator — the model is genuinely available there on Apple Silicon hosts.
- **Runs** (`Core/AI/RunFinder.swift`, `Features/Home/RunRail.swift`; shown in the UI as **The Jams** — "run" is code-only, since to heads a run is a stand of shows at one venue): the app's unit of listening is the run, not just the show. `RunFinder` finds runs inside any catalog setlist by linking neighbours through the catalog's segue flag *or* the KB segue graph (`songs.json` `seguePartners`) — the catalog only flags segues on ~200 of 1,600 setlists, so partners do most of the work; Drums/Space are transparent bridges and never open or close a run. `RunShelfPlanner` picks the home page's daily shelf (rotating canon from `runs.json`, favorite era first, plus catalog runs from top-rated nights, no repeated sequence). `RunShelfModel` plays a run as its own queue (only the run's tracks) or stitches every run on the shelf into one cross-show queue; if the night's best tape is a partial it tries the night's other tapes. `RunResolver` anchors a run to a tape's tracks — bridge tracks are free and bridge keys optional, so "Truckin' > Drums > The Other One" resolves on tapes that fold Drums into Truckin'. Curated runs must be real: `1989-07-07` has no Morning Dew on any tape (the JFK run is Scarlet > Fire). A run's running time comes from the tape's tracks: the shelf pins every pick to a tape up front (`ResolvedRun`, `RunLength`) — from the catalog's `recording_tracks` first (the pick's own tape, then the night's others in quality order, no network at all, file names included so playback needs no detail fetch either), falling back to live `/metadata` calls with the same multi-tape fallback — so cards say "26 min", the blurb says how long the shelf runs end to end, and "Play the run" is instant. `OfflineRuns` lists the runs on downloaded shows with no network; `RunRows` builds the CarPlay "Runs" tab's rows (first tab: on-device runs, then today's shelf, each row "date · venue · length", plus play-everything rows) so the wording is tested without a CarPlay scene.
- **Smart collections** (`Core/AI/SmartCollections.swift`, `SmartCollectionEngine.swift`): a pure planner (`SmartCollectionPlanner`) turns clock/calendar/listening trends into grounded briefs; the AI provider names each shelf and orders picks constrained to offered candidates. Results cache in SwiftData per day/daypart slot.
- **Persistence**: SwiftData stores in `Core/Persistence/` (cache, history/taste profile, library, smart collections, journeys). The container has two configurations (`ModelContainerFactory`): `default.store` for device-local models, and `shakedown-cloud.store` for `ShowCollection`/`CollectionItem`/`JournalEntry`, which opens with CloudKit private-database sync (`iCloud.com.deadhead.ai`) when a persisted Apple sign-in exists and local-only otherwise (never on simulator builds — without the runtime entitlement CloudKit traps asynchronously and uncatchably, so `ModelContainerFactory` forces sync off there) — same file either way, so flipping sync moves no data. Sign-in/out posts `.shakedownAuthChanged` and `ShakedownAIApp` rebuilds the whole `AppEnvironment` (container mode is fixed at creation). The synced models carry no unique constraints (CloudKit forbids them) — `LibraryStore.dedupAfterSync()` collapses duplicates deterministically at launch/foreground. `CloudStoreMigrator` one-time-copies legacy rows into the cloud store from a `pre-cloud-backup.store` file snapshot (flag `cloudStoreMigrationV1Done`). Cache tables hold opaque encoded domain structs; SwiftData models never cross actor boundaries — domain structs (`Core/Models/DomainModels.swift`) do.
- **Audio**: `PlayerEngine` (`Core/Audio/`) wraps an `AVQueuePlayer` with an explicit queue as source of truth: the next track is preloaded so natural boundaries are gapless (segues!), and on auto-advance the engine catches its state up via `adoptAdvancedItem()` — manual skips rebuild the AVQueue. End-of-content is signaled only by `AVPlayerItem.didPlayToEndTimeNotification`, never by interrogating playback state. Also: sleep timer (minutes with fade-out, or end-of-track), lock-screen ±15s skips, AirPlay picker (`AirPlayRoutePicker` in the full player). Handles background audio, Now Playing, remote commands, interruptions. Listening events flow to `HistoryStore` via a callback set in `AppEnvironment`.
- **Siri / App Intents** (`Features/Intents/PlaybackIntents.swift`): `AudioPlaybackIntent`s ("play tonight's show", "play a show by date") that resolve through the providers and drive `PlayerEngine` via `AppEnvironment.current` (a weak static set on init — the hook for non-SwiftUI entry points). **CarPlay** (`Features/CarPlay/`) is written but dormant: it ships no entitlement until Apple grants `com.apple.developer.carplay-audio` (request at developer.apple.com/carplay) — adding the entitlement before approval would break TestFlight signing. Enable per the comment atop `CarPlaySceneDelegate.swift`.
- **Offline downloads** (`Core/Downloads/`): `DownloadManager` drives a background `URLSession` (id `ai.deadheads.downloads`; relaunch events land in `App/AppDelegate.swift`) that saves a show's MP3s to `Application Support/Downloads/{identifier}/` (backup-excluded); `DownloadStore` (`Core/Persistence/`) indexes them in the local SwiftData store, persisting full `Show`/`RecordingDetail` snapshots so downloaded shows open with no network. Playback needs no player changes: `OfflineFirstStreamingProvider` decorates `ArchiveStreamingProvider` and returns the `file://` URL when a track is on disk. The live `URLSession` is cached process-globally (auth changes rebuild `AppEnvironment`, and duplicate background-session identifiers are an error); tests/previews inject an ephemeral session via `makeSession`. Downloads default to Wi-Fi-only (Settings toggle). ⚠️ Background download tasks fail instantly with `NSURLErrorDomain Code=-1 "unknown error"` in `CODE_SIGNING_ALLOWED=NO` builds (nsurlsessiond can't attribute the session) — to exercise downloads in the simulator, build *without* that flag (ad-hoc signing needs no account); unit tests are unaffected. Also: `URL.path()` returns a percent-encoded path that `FileManager` rejects (the store's paths contain spaces and literal `%`) — always use `path(percentEncoded: false)` for FileManager calls.

## Voice

Every user-facing string and every AI prompt follows [VOICE.md](VOICE.md): the app talks like an old Deadhead (the DECnotes Dead conferences are the reference) — "show" not "concert", "tape"/"board"/"aud", "the boys", first names for the band, segues written `A > B`, dates like `5/8/77`, plain first-person copy with no marketing polish. Feature names in the UI: The Jams (never "runs" in copy — a run is a venue stand to heads; code keeps `Run*` names), Mix Tapes (code still says `Playlist`), Shelves, Ask the Universe (search), Show Reviews / What the Heads Say, Listening Notes, Other Tapes. Keep new copy in that register.

## Secrets

`Config/Secrets.xcconfig` is gitignored and optionally `#include?`d from `Config/Shared.xcconfig`; copy `Config/Secrets.example.xcconfig` to bundle an OpenAI key locally. CI injects `OPENAI_API_KEY` from a repo secret. Never commit a real key.
